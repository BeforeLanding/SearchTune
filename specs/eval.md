# 评测 Spec

> 上位约束：`CONSTITUTION.md` 原则 1、2。评测集与商品池见 `specs/data.md` §4、§5；环境、工具与预算见 `specs/training.md` §2。
>

## 1. 评测集与使用规则

| 集合 | 规模 | 允许的用途 | 禁止的用途 |
|---|---|---|---|
| `dev-quick` | 200 query | 开发期冒烟、改代码后的回归检查 | — |
| `dev` | 500 query | 调参、选 checkpoint、迭代 prompt、指导迭代的误差分析 | — |
| `test` | 1000 query | 每个里程碑**最终选定**的模型跑一次；baseline 跑一次 | 调参、选 checkpoint、改 prompt、指导迭代的误差分析 |

- 每次在 `test` 上评测都要记入 `EXPERIMENTS.md`，并标注“test”。test 的总运行次数是要公开报告的数字。
- checkpoint 选择一律按 `dev` 上的主指标。
- 在 test 上看轨迹只用于最终报告，看完不能回头改模型、prompt 或环境。

## 2. 指标

### 2.1 主指标

**NDCG@10**：对 Agent 提交的前 10 个商品，按 `specs/data.md` §2 的增益计算（U 记为 0），再对所有 query 取算术平均。

- 提交不足 10 个时，空位按 0 计算。
- 没有有效提交（格式错误、预算耗尽、截断）的 episode，NDCG 记为 0，**计入分母**。
- 理想排序用池内全部标注商品的真实增益计算。

### 2.2 次要指标（都要报告，不作为验收门槛，除非 §6 另有说明）

| 指标 | 定义 | 关注点 |
|---|---|---|
| E-Recall@10 | 提交的前 10 个中 E 商品数 / min(池中 E 的数量, 10) | 找全了没有 |
| 坏例率 BadRate@3 | 前 3 个中出现任何 I 商品的 query 比例 | 对应工业界的“坏例率” |
| U 占比 | 前 10 个中干扰商品的比例 | 配合 §8 的抽检解读 |
| 工具调用数 | 每个 episode 的 `search`、`view` 次数及合计 | 效率 |
| 生成 token 数、单 episode 耗时 | 平均值和 P90 | 成本 |
| 格式失败率、预算耗尽率、截断率 | 各类无有效提交的比例 | 稳定性 |
| 难例切片 NDCG@10 | 见 §2.3 | 在哪类 query 上有提升 |

### 2.3 难例切片

用确定性的规则给 query 打切片标签（一个 query 可以属于多个切片），切片成员列表在锁定前生成并进 git：

| 切片 | 规则（实现时细化，规则本身写进 `data/STATS.md`） |
|---|---|
| 否定 | 含 `without` / `no` / `free` / `non` 等否定词 |
| 数量规格 | 含数字加单位、`pack`、尺码等 |
| 兼容型号 | 含 `for` 加型号，或字母数字混合的型号串 |
| 指定品牌 | 含商品目录中出现过的品牌名 |
| 长 query | 词数 ≥ 6 |

切片对应 `specs/labeling-guideline.md` 中的硬约束和软约束类型，误差分析时两者一并使用。

## 3. 评测输出协议

所有被评测的系统（包括非 LLM 的 baseline）都先产出**轨迹文件**，再由独立的打分脚本计算指标。

轨迹文件每行一个 episode：

```json
{"query_id": "...", "submitted": ["pid1", "pid2"], "status": "ok",
 "turns": [{"role": "assistant", "content": "...", "tool_call": {"name": "search", "args": {"query": "..."}}},
           {"role": "tool", "name": "search", "content": "..."}],
 "n_search": 2, "n_view": 3, "gen_tokens": 412, "wall_time_s": 3.1}
```

规则：

- `status` 取值：`ok` / `format_error` / `budget_exhausted` / `truncated`。只有 `ok` 的 `submitted` 才计分，其余一律按空提交计算。
- **解码**：评测时 greedy（temperature = 0）。工具全部是确定性的（BM25 同分时按 `product_id` 排序），因此同一模型的评测结果可以复现。
- **环境版本**：轨迹文件的元数据必须记录环境版本（工具定义、预算、返回格式；见 `specs/training.md` §2）。
- 非 LLM baseline 的 `turns` 为空，只填 `submitted`。

## 4. Prompt 与环境版本

- system prompt 存为 `prompts/agent_v<N>.txt`，其中的相关性定义从 `specs/labeling-guideline.md` 提炼。
- 实验记录必须写明 prompt 版本和环境版本。
- prompt 只能在 `dev` 上迭代。锁定时选定的 prompt 和环境版本用于全部 LLM baseline 和训练。

## 5. Baseline

| ID | 内容 | 作用 | 是否必须 |
|---|---|---|---|
| B0 | 用原始 query 调一次 `search`，直接提交前 10 | 下限；检查环境和打分器 | 必须 |
| B1 | 零样本 Agent：待训练的基座模型，同一套工具和预算 | 衡量 RL 带来的提升 | 必须 |
| B2 | 零样本单步改写：基座模型改写一次 query → `search` → 提交前 10 | L1 的起点 | 必须 |
| B3 | 检索 + 精排流水线：原始 query 做 BM25 取前 30 → 用 ESCI 训练的 DeBERTa-v3-base 按期望增益重排 → 提交前 10 | 工业界传统做法的参照；**查看预算与 Agent 对齐**（都是约 30 个商品） | 必须 |
| B4 | 更强的开源模型（Qwen3.5-9B）零样本 Agent | 参照上限；同时也是 L2 冷启动轨迹的来源 | 可选 |

B3 的说明：它对 30 个商品都看了完整文本，而 Agent 只看得到检索结果里的标题和少量 `view` 的详情，所以这个对比**对 B3 有利**。B3 作为参照如实报告，**不作为验收门槛**。

## 6. 统计判定与验收

**显著性**：在 test 上按 **query 做配对 bootstrap**（1000 次重采样，seed = 20261031），计算两个系统主指标之差的 95% 置信区间。**区间下界 > 0** 才算“显著优于”。

| 里程碑 | 验收条件（全部满足） |
|---|---|
| M1 L1 | ① NDCG@10 显著优于 B0 和 B2；② 相对 B0 的提升 ≥ Δ₁（锁定时填写）；③ 格式失败率 < 1% |
| M2 L2 | ① NDCG@10 显著优于 B1 和 M1；② BadRate@3 不高于 M1；③ 格式失败率与预算耗尽率合计 < 2% |

M2 没有达标不代表项目失败：按宪章要求如实记录结论和原因分析即可。与 B3 的对比在两个里程碑都要报告。

## 8. 误差分析与漏标抽检

### 8.1 轨迹误差分类

每个失败的 episode 打**一个主类**：

| 标签 | 类型 | 判定方式 |
|---|---|---|
| A1 | 检索失败 | 池中有 E，但所有 `search` 结果里一个 E 都没有出现 |
| A2 | 改写偏离 | 改写后的 query 丢掉或改变了原 query 的硬约束 |
| A3 | 未核验 | 提交了违反硬约束的商品，且提交前没有 `view` 过它 |
| A4 | 核验后仍判错 | `view` 过，仍然提交了违反硬约束的商品 |
| A5 | 排序错误 | 看到过 E，但排在非 E 商品后面 |
| A6 | 预算或格式 | 预算耗尽、格式错误、截断 |
| A7 | 疑似漏标 | 被扣分的 U 商品实际上相关（来自 §8.2 的抽检） |
| A8 | 疑似标注噪声 | 判断符合 `specs/labeling-guideline.md`，但与人工标签不一致 |

A1、A5、A6 可以从轨迹自动判定；A2–A4、A7、A8 需要人工或 LLM 辅助判断。

- 每个里程碑：在 **dev** 上抽 100 个失败 episode（seed 固定）做分析，并和上一阶段对比。这部分可以用来指导下一步迭代。
- 最终报告：在 test 上做同样的分析，只用于报告。

### 8.2 漏标抽检

U 商品按不相关计分，但其中可能有真正相关的商品。最终报告前：

- 从 M2 模型在 test 上提交的前 10 中抽 100 个 U 商品，按 `specs/labeling-guideline.md` 用 Qwen3.5-9B 判档，再人工复核其中 20 个。
- 报告估计的漏标率，以及“把判为 E/S 的 U 商品按相应增益计入”时的 NDCG@10（敏感性分析，**只用于报告，不替代主指标**）。

## 9. 环境与评测管线的验收

- [ ] NDCG@10、E-Recall@10、BadRate@3 在手算的小例子上结果一致，包括提交不足 10 个和无有效提交的情况（单元测试）
- [ ] 同一个模型、同一个环境版本，greedy 评测两次的轨迹逐字一致
- [ ] 同一份轨迹文件、同一个 seed，bootstrap 结果逐位一致
- [ ] 非 `ok` 状态的 episode 按 0 分计入分母（单元测试）
- [ ] 工具返回给 Agent 的内容中不含 `label`、`gain`、`source`（单元测试）
- [ ] 一条命令能从轨迹文件输出 §2 的全部指标，并生成可直接粘贴进 `EXPERIMENTS.md` 的一行
