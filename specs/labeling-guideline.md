# 相关性判定标准

> 上位约束：`CONSTITUTION.md` D1、D2；标签集合见 `specs/data.md` §2。

## 0. 本文的用途

使用 ESCI 时，测试集标签是原始人工标签，本文**不用于重标测试集**。在搜索 Agent 项目里，它有四个用途：

1. **Agent 的相关性定义**：system prompt 里“什么商品算相关”的说明从本文提炼，二者保持一致（prompt 版本见 `specs/eval.md` §4）
2. **难例切片的依据**：§1 的硬约束和软约束类型，对应 `specs/eval.md` §2.3 的 query 切片
3. **轨迹误差分析**：判断 Agent 是否丢掉了硬约束（A2）、是否提交了违反硬约束的商品（A3、A4），以及单个商品判断层面的 §5 错误类型
4. **漏标抽检**：`specs/eval.md` §8.2 中给干扰商品（U）判档时，按本文执行

ESCI 原始标注有噪声，个别样本的人工标签会与本文判定不一致。这是已知现象：误差分析时标为 `T9 疑似标注噪声`，**不修改测试集标签**。

## 1. 先拆 query

判定前先把 query 拆成三部分：

| 成分 | 说明 | 例：`nike running shoes men` |
|---|---|---|
| 品类 | 用户要的是哪类东西 | 跑鞋 |
| 硬约束 | 不满足就**用不了或明确不想要** | 男款 |
| 软约束 | 不满足**仍可凑合用** | 品牌 Nike |

硬约束的典型类型：

- **兼容 / 型号**：`iphone 13 case` 中的 iPhone 13
- **否定 / 排除**：`sugar free`、`without bluetooth`、`non toxic`
- **决定能否使用的核心规格**：电池型号（AA vs AAA）、接口类型、尺码
- **适用对象**：男款 / 女款 / 儿童、犬用 / 猫用（明确写在 query 里时）

软约束的典型类型：品牌、颜色、数量 / 包装规格、风格、材质（材质本身是需求核心时除外）。

> 品牌默认是软约束。若 query 几乎只有品牌加型号（如 `airpods pro 2`），型号就成了硬约束。

## 2. 判定流程

按顺序回答，命中即停：

```
Q1 商品是不是 query 要的品类（或功能上等价的东西）？
   ├─ 否 → Q1a 它是不是和目标商品搭配使用的东西？
   │        ├─ 是 → C
   │        └─ 否 → I
   └─ 是 → Q2 是否违反任一硬约束？
            ├─ 是 → I
            └─ 否 → Q3 是否违反任一软约束？
                     ├─ 是 → S
                     └─ 否 → E
```

补充规则：

- **无法从商品信息验证的约束不作为降级理由**。例如 `laptop under 500` 中的价格在商品字段里没有，按其余信息判。
- **商品信息本身矛盾**（标题说 AA，卖点说 AAA）时，以标题为准。
- **query 有歧义**时，取最常见的解读；把歧义本身记为 `T7`，不强求一致。
- 档位描述的是“这个商品对这个 query 的满足程度”，不考虑商品质量、价格高低或评分。

## 3. 各档定义

**E（Exact）**：属于目标品类，满足 query 中所有可验证的约束。

**S（Substitute）**：属于目标品类或功能等价，满足所有硬约束，但违反至少一个软约束。用户看到会觉得“不是我要的那个，但也能用”。

**C（Complement）**：不是用户要的东西，但通常和目标商品一起使用。用户看到会觉得“这不是我要的，但可能也用得上”。

**I（Irrelevant）**：品类不对且不是配套品，或品类对但违反了硬约束。用户看到会觉得“这对我没用”。

## 4. 示例

| query | 商品 | 档位 | 依据 |
|---|---|---|---|
| `nike running shoes men` | Nike 男款跑鞋 | E | 全部满足 |
| `nike running shoes men` | Adidas 男款跑鞋 | S | 违反软约束：品牌 |
| `nike running shoes men` | Nike 运动袜 | C | 品类不对，但搭配使用 |
| `nike running shoes men` | Nike 女款凉鞋 | I | 品类不对，且不是配套品 |
| `aaa batteries 24 pack` | AAA 电池 24 节装 | E | 全部满足 |
| `aaa batteries 24 pack` | AAA 电池 48 节装 | S | 违反软约束：数量 |
| `aaa batteries 24 pack` | AA 电池 24 节装 | I | 违反硬约束：电池型号 |
| `aaa batteries 24 pack` | AAA 电池充电器 | C | 配套使用 |
| `iphone 13 case` | iPhone 13 硅胶壳 | E | 全部满足 |
| `iphone 13 case` | iPhone 13 Pro 手机壳 | I | 违反硬约束：型号不兼容 |
| `iphone 13 case` | iPhone 13 钢化膜 | C | 配套使用 |
| `sugar free gummy bears` | 普通含糖小熊软糖 | I | 违反硬约束：否定条件 |
| `sugar free gummy bears` | 无糖水果软糖（非小熊形） | S | 违反软约束：形状 |

## 5. 误差分析分类

这是**单个商品判断层面**的错误分类，用于 Agent 提交了错误商品时细分原因（对应 `specs/eval.md` §8.1 的 A3、A4），以及漏标抽检中的判档分歧。每个错例打**一个主类**（必要时附一个次类）：

| 标签 | 类型 | 典型表现 |
|---|---|---|
| T1 | 品类判断错 | 把配件当主体，或把主体当配件 |
| T2 | 兼容 / 型号约束 | 型号、接口、适配对象不符，却判成 E/S |
| T3 | 否定约束 | 忽略 `without` / `free` / `non` 等 |
| T4 | 软约束误判 | 品牌、颜色差异被判成 I，或被判成 E |
| T5 | 数量 / 规格 | 数量、尺寸、容量的处理与本文不一致 |
| T6 | C 与 I 混淆 | 配套品和无关品区分错误 |
| T7 | query 歧义 | query 本身有多种合理解读 |
| T8 | 商品信息缺失 | 关键字段为空，信息不足以判断 |
| T9 | 疑似标注噪声 | 模型判断符合本文，但与人工标签不一致 |

T9 与 `specs/eval.md` §8.1 的 A8 是同一类问题，在轨迹层面统一按 A8 报告。

## 6. 维护规则

- 修改档位定义或判定流程，要同步修改 prompt 并升 prompt 版本（见 `specs/eval.md` §4）。
- 在测试集锁定之后修改本文，**不能**以此为由重新解释已有的测试结果；只能新开实验，并在 `DECISIONS.md` 记录原因。
