# 训练 Spec

> 上位约束：`CONSTITUTION.md` D2（四档分类）、D3（单卡 24GB，基座 ≤ 4B，LoRA）、D4（SFT + 一种后训练方法）。
> 评测口径一律以 `specs/eval.md` 为准，本文不重新定义指标。

## 1. 路线总览

```
基座（零样本 = B1）
  └─ SFT，直答模式 ............................ M1
       └─ GRPO，直答模式，代价敏感奖励 ......... M2
```

D4 定为 **GRPO**，不选 DPO。理由：

- 本任务有确定的标准答案，奖励可以直接由规则算出，不需要构造偏好对，也不需要奖励模型。
- 四个档位的错误代价不同：把不相关判成完全匹配，比把 E 判成 S 严重得多。交叉熵对所有错误一视同仁，GRPO 可以把这种代价差异直接写进奖励（§5.2）。这是它相对 SFT 能多给出的东西，也是 M2 要验证的假设。
- 如果用 DPO，chosen 是正确档位、rejected 是错误档位，本质上和带对比项的分类损失差不多，能讲的东西少。

已知风险：在直答模式下，SFT 用交叉熵训练后已经接近分类的最优解，GRPO 的提升可能很小。所以 M2 的验收允许“没达标但结论清楚”（见 `specs/eval.md` §6），推理模式作为可选的补充实验（§6 中的 E8）。

## 2. 模型选择

| 角色 | 模型 | 说明 |
|---|---|---|
| 主模型 | Qwen3.5-2B | 2026-03 发布的小尺寸系列，满足 D3；2B 在 24GB 显存上做 GRPO 余量充足，迭代快 |
| 规模对照 | Qwen3.5-4B | 只在 E5 中使用同一套 SFT 配方，回答“换大一号能多拿多少” |
| 备选 | Qwen3-1.7B / Qwen3-4B | 若 Qwen3.5 未通过 §2.1 的检查，整体换成这一组 |
| B3 cross-encoder | `microsoft/deberta-v3-base` | KDD Cup 2022 ESCI 赛道中常用的 encoder，作为非 LLM 强基线 |

B1 就是主模型（Qwen3.5-2B）零样本加锁定的 prompt。

### 2.1 开工前的模型检查（M0 内完成，结果记入 `DECISIONS.md`）

- [ ] 许可证允许研究使用
- [ ] 只用文本输入时能正常加载和推理（Qwen3.5 Small 原生支持多模态，需确认纯文本路径没有额外开销或报错）
- [ ] chat template 能关闭思考模式，直答模式下不输出思考内容
- [ ] `E` `S` `C` `I` 在 tokenizer 中各是单个 token，且在答案位置可以直接取到 logits；不满足就换成能满足的标记，并同步改 prompt
- [ ] 训练框架（TRL + PEFT）和 HF transformers 推理都支持该模型；vLLM 只有 E8 需要，不支持时 E8 改用 HF 生成

任一项不通过，就换到备选模型，不在适配上耗时间。

## 3. 输入格式

- 使用 chat template；system 段写档位定义（从 `specs/labeling-guideline.md` 提炼，与 eval 的 prompt 同源），user 段写 query 和商品信息。
- 商品信息 v1 包含：`title`、`brand`、`color`、`bullets`。**不含** `description`（噪声大、篇幅长），是否加入由 E4 回答。
- 商品文本截断到 **192 token**；截断顺序是先截 `bullets`，再截 `title`。
- 整条输入上限 **512 token**。实际长度分布写入 `data/STATS.md`，超长比例 > 1% 时回到本节调整。
- 缺失字段写成 `N/A`，不省略字段名，让模型看到“这个信息是缺的”。
- 输出：直答模式只输出一个档位字母（与 `specs/eval.md` §3 一致）。

输入模板的版本号与 eval 的 prompt 版本分开管理，存为 `prompts/sft_input_v<N>.txt`。

## 4. SFT

### 4.1 数据

| 项 | 设定 |
|---|---|
| 来源 | `specs/data.md` 的 train split |
| 主训练集 | **按 query 整组抽样**，直到累计约 200k pair，seed = 20261031 |
| 标签分布 | 保持自然分布（再平衡由 E3 回答） |
| 损失 | 只对答案 token 计算 loss |

SFT 实际使用的 query_id 列表写入 `data/splits/sft_main.txt`，B3 使用同一份列表。

### 4.2 超参数（v1）

| 项 | 值 |
|---|---|
| LoRA | r = 16，alpha = 32，dropout = 0.05，作用于全部线性层 |
| 学习率 | 2e-4，cosine 衰减，warmup 3% |
| epoch | 1 |
| 有效 batch | 64（单卡 batch × 梯度累积） |
| 精度 | bf16 |
| seed | 20261031 |
| 评估与保存 | 每训练 10% 的步数在 `dev-quick` 上评估并保存一次；最终按 `dev` 主指标选 checkpoint |

超参数只在 `dev` 上调，且只在 E1 跑通之后调，一次只改一项。

## 5. GRPO

### 5.1 设定

| 项 | 值 |
|---|---|
| 起点 | M1 选定的 SFT checkpoint（LoRA 合并后再挂新的 LoRA） |
| 数据 | train 中**未进入 SFT 主训练集**的 query，按标签分层抽约 20k pair；查询列表写入 `data/splits/grpo_main.txt` |
| 模式 | 直答模式，`max_new_tokens = 8` |
| 每组采样数 G | 8 |
| 采样温度 | 1.0 |
| KL 系数 β | 0.04 |
| 学习率 | 1e-5 |
| 选 checkpoint | 按 `dev` 主指标 |

数据要和 SFT 分开，这样 GRPO 看到的是新样本，提升不能归因为“同一批数据多学了一遍”。

### 5.2 奖励（v1：代价矩阵）

行是真实标签，列是预测标签：

| 真实 \ 预测 | E | S | C | I |
|---|---|---|---|---|
| **E** | 1.0 | 0.3 | 0.0 | −0.5 |
| **S** | 0.3 | 1.0 | 0.2 | 0.0 |
| **C** | 0.0 | 0.2 | 1.0 | 0.3 |
| **I** | −0.5 | 0.0 | 0.3 | 1.0 |

无法解析的输出奖励为 −1.0。

设计意图：

- **E 与 I 互判扣分最重**：前者会把不相关商品排到前面，后者会把完全匹配的商品过滤掉，在线上都是最伤的错误。
- **相邻档位给部分分**：E/S、S/C、C/I 之间的误判在语义上更接近。
- 风险：部分分可能让模型倾向多数类，伤害 macro-F1。所以 E7 用 0/1 奖励做对照；如果代价矩阵拉低了 S/C 的召回，就考虑按类别频率加权（再开一个实验，不改 v1）。

奖励矩阵是一项设计取舍，定稿后记入 `DECISIONS.md`。

## 6. 实验矩阵

每个实验只改一个变量。所有比较先看 `dev`；只有里程碑最终选定的模型才跑 `test`。

| ID | 优先级 | 要回答的问题 | 相对谁改了什么 |
|---|---|---|---|
| E1 | 必做 | SFT 能比零样本和 cross-encoder 好多少？ | 主配方（§3、§4），对照 B1、B3 |
| E3 | 应做 | 再平衡标签分布能否提升 S/C？ | E1 → 训练集中 S/C 上采样到各占 ≥ 15% |
| E6 | 必做 | 代价敏感的 GRPO 能否超过 SFT？ | 最佳 SFT → GRPO（§5） |
| E7 | 应做 | 提升来自代价矩阵还是来自 RL 本身？ | E6 → 奖励换成 0/1 |
| E2 | 可做 | 数据量的收益曲线 | E1 → 训练集 50k pair |
| E4 | 可做 | `description` 有没有用？ | E1 → 输入加入 `description` |
| E5 | 可做 | 换大一号模型多拿多少？ | E1 → 基座换成 Qwen3.5-4B |
| E8 | 可做 | 推理模式能否突破直答的上限？ | 基座 → 开启思考模式做 GRPO，`max_new_tokens = 512`，奖励同 v1 |

- M1 的候选是 E1–E5 中 `dev` 主指标最好的那个，选定后跑一次 `test`。
- M2 的候选是 E6–E8 中 `dev` 主指标最好的那个。
- 按宪章的规则，里程碑超时 50% 时从“可做”开始砍，“必做”不砍。

开工时只有估算；E1 跑完后用实测吞吐回填。

| 项 | 估算 | 实测 |
|---|---|---|
