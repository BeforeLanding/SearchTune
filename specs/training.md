# 训练 Spec

> 上位约束：`CONSTITUTION.md` D2（商品搜索 Agent）、D3（单卡，策略 ≤ 4B，LoRA）、D4（L1 GRPO；L2 冷启动 SFT + GRPO）。
> 评测口径一律以 `specs/eval.md` 为准，本文不重新定义指标。

## 1. 路线总览

```
基座零样本（B1 零样本 Agent、B2 零样本单步改写）
 ├─ L1：单步改写 + GRPO ..................................... M1
 └─ L2：冷启动 SFT（B4 轨迹经拒绝采样）→ 多轮 GRPO ............. M2
```

- **L1** 是最小可行版本：单轮生成、奖励即时可算，用来先把环境、奖励和训练管线跑通，也作为 L2 必须超过的对照。
- **L2** 是项目主体：多轮工具调用，奖励在 episode 结束时由提交列表计算。
- L2 从基座出发，不从 L1 继续训练，这样两者的对比更干净。

## 2. 环境 `env_v1`

环境版本在评测锁定时冻结（`specs/eval.md` §7），本节任何改动都要升版本号。

### 2.1 L2 的工具

| 工具 | 参数 | 返回给 Agent 的内容 |
|---|---|---|
| `search` | `query: str` | 在本 query 的商品池里做 BM25（索引标题、品牌、卖点），返回前 10 个：`[product_id] 标题（截断到 32 token）\| 品牌` |
| `view` | `product_id: str` | 标题、品牌、颜色、卖点（卖点截断到 200 token）；不含商品描述 |
| `submit` | `product_ids: list[str]` | 结束 episode。按顺序取前 10 个；去掉重复项，不在池中的 id 丢弃并计数 |

- BM25 同分时按 `product_id` 排序，保证结果确定。
- 缺失字段显示为 `N/A`。
- **返回内容里永远不含 `label`、`gain`、`source`**。

### 2.2 L2 的预算与格式

| 项 | 值 |
|---|---|
| 工具调用上限 | `search` 和 `view` 合计 6 次。用完后环境提示“必须提交”，再给一轮机会；仍未提交记为 `budget_exhausted` |
| 每轮生成上限 | 512 token |
| 整条轨迹上下文上限 | 6144 token，超出记为 `truncated` |
| 工具调用格式 | 模型原生的函数调用格式（hermes），由 verl 的 ToolAgentLoop 解析；解析失败记为 `format_error` |
| 思考模式 | 关闭；允许模型在工具调用前写简短的分析 |

查看预算约为 3 次 `search` × 10 个结果，即约 30 个商品，和 B3 对齐（`specs/eval.md` §5）。

### 2.3 L1 的环境

单轮：模型输出一行改写后的 query（`max_new_tokens = 64`，最多 32 个词），环境用它调一次 `search`，直接提交前 10 个。输出为空或超长记为 `format_error`。

## 3. 模型

| 角色 | 模型 | 说明 |
|---|---|---|
| 策略模型（主） | Qwen3.5-2B | 满足 D3；多轮 rollout 的显存余量相对充足 |
| 策略模型（规模对照） | Qwen3.5-4B | 只在 E9 中使用，T0 实测可行才做 |
| 本地冒烟 | Qwen3.5-0.8B | 本地 8GB 显卡上验证训练管线能跑通，结果不进入比较 |
| 冷启动轨迹来源 / B4 | Qwen3.5-9B | 在云端用 vLLM 推理 |
| B3 精排模型 | `microsoft/deberta-v3-base` | 用 train split 的 (query, 商品, 标签) 训练四分类，按期望增益排序 |
| 备选 | Qwen3 同尺寸系列 | 若 Qwen3.5 未通过 §3.1 的检查，整体替换 |

### 3.1 开工前的模型检查（T0 完成，结果记入 `DECISIONS.md`）

- [ ] 许可证允许研究使用
- [ ] 只用文本输入时能正常加载和推理（Qwen3.5 Small 原生支持多模态）
- [ ] chat template 支持函数调用，且能被 verl 的 hermes 解析器正确解析
- [ ] 能关闭思考模式
- [ ] verl（rollout 用 vLLM 或 SGLang）+ LoRA 能在单卡上跑通 L2 的 1 个训练步

任一项不通过，就换到备选模型，不在适配上耗时间。

## 4. 奖励

### 4.1 L1

- r = 提交列表的 NDCG@10（与 `specs/eval.md` §2.1 同一实现）
- `format_error`：r = −0.2

### 4.2 L2（v1）

```
r = NDCG@10
    − 0.3 × （前 3 个中 I 商品的数量 / 3）
    − 0.02 × max(0, 工具调用次数 − 4)
非 ok 状态：r = −0.2
```

| 项 | 作用 |
|---|---|
| NDCG@10 | 主目标，与评测主指标一致 |
| 坏例惩罚 | 对应 BadRate@3：前排出现不相关商品是线上最伤的错误。只惩罚有标注的 I，不惩罚 U，避免把漏标风险放大 |
| 调用成本 | 前 4 次调用免费，之后每次扣一点，抑制无意义的反复查看 |

奖励的每一项都只依赖池中的标注，**不需要奖励模型**。E5 对照只保留 NDCG@10 的版本。奖励函数与评测打分器共用同一份 NDCG 实现。

## 5. 训练配置

训练框架统一用 **verl**：GRPO 用 verl 的 AgentLoop（L2 用 ToolAgentLoop），SFT 用 verl 的多轮 SFT。B3 用 HF Trainer。

### 5.1 L1 GRPO

| 项 | 值 |
|---|---|
| 起点 | 基座模型 |
| 数据 | `data/splits/rl_l1.txt`：从 train 中按 query 抽 8000 个 |
| 每组采样数 G | 8 |
| 采样温度 | 1.0 |
| LoRA | r = 32，alpha = 64，作用于全部线性层 |
| 学习率 | 2e-5 |
| KL 系数 | 0.001 |
| 动态过滤 | 丢弃组内奖励方差为 0 的组（全对或全错），参考 DAPO 和 RAGEN-2 的做法；E2 关闭此项做对照 |
| 选 checkpoint | 按 `dev` 主指标 |

### 5.2 L2 冷启动 SFT

| 项 | 值 |
|---|---|
| 轨迹来源 | B4（Qwen3.5-9B）在 `data/splits/sft_traj.txt`（train 中抽 4000 个 query）上运行 `env_v1` |
| 采样 | 每个 query 采 4 条，温度 0.7 |
| 拒绝采样 | 每个 query 只保留 NDCG@10 最高的一条，且要求状态为 `ok`、NDCG@10 ≥ 0.6、不低于该 query 上 B0 的分数 |
| 损失 | 只对 assistant 生成的 token 计算，工具返回的内容不计 loss |
| LoRA | 同 §5.1 |
| 学习率 / epoch | 1e-4 / 2 |

轨迹的保留率要写入 `EXPERIMENTS.md`。保留率太低（< 20%）时，先回头检查环境和 prompt，再决定要不要放宽阈值。

### 5.3 L2 GRPO

| 项 | 值 |
|---|---|
| 起点 | §5.2 的 SFT checkpoint（E6 改为直接从基座出发） |
| 数据 | `data/splits/rl_l2.txt`：从 train 中抽 3000 个 query，与 `sft_traj` 不相交 |
| 每组采样数 G | 8 |
| 优势估计 | GRPO，整条轨迹一个优势值；工具返回的 token 不参与 loss |
| 采样温度 | 1.0 |
| LoRA / 学习率 / KL | 同 §5.1 |
| 动态过滤 | 同 §5.1 |

### 5.4 训练过程监控

除奖励曲线外，每隔固定步数在 `dev-quick` 上记录：

- 策略熵
- 工具调用次数分布、`format_error` 率、`budget_exhausted` 率
- **模板坍塌的简易指标**：第一次 `search` 的 query 与原 query 完全相同的比例；不同 query 的首轮输出两两之间的相似度。RAGEN-2 发现熵稳定并不代表推理健康，模型可能退化成和输入无关的固定模板，这两个指标用来尽早发现这种情况。

出现明显坍塌（例如首轮输出高度雷同、奖励停滞）时，先停下来分析，并记入 `EXPERIMENTS.md`。

## 6. 数据子集

| 列表 | 来源 | 规模 | 用途 |
|---|---|---|---|
| `rl_l1.txt` | train | 8000 query | L1 GRPO |
| `sft_traj.txt` | train | 4000 query | 生成 L2 冷启动轨迹 |
| `rl_l2.txt` | train | 3000 query | L2 GRPO |

三份列表都按 query 抽样，seed = 20261031。`sft_traj` 与 `rl_l2` 必须不相交，这样 RL 阶段看到的都是新 query。`rl_l1` 不受这条限制，因为 L1 和 L2 是两条独立的训练线。

## 7. 实验矩阵

每个实验只改一个变量。所有比较先看 `dev`；只有里程碑最终选定的模型才跑 `test`。

| ID | 优先级 | 要回答的问题 | 相对谁改了什么 |
|---|---|---|---|
| E1 | 必做 | RL 训练的单步改写能超过零样本改写和原始 query 吗？ | L1 主配方（§5.1），对照 B0、B2 |
| E3 | 必做 | 只做冷启动 SFT 能到什么水平？ | 基座 → §5.2 |
| E4 | 必做 | 多轮 GRPO 在 SFT 之上能提升多少？ | E3 → §5.3，奖励 v1 |
| E5 | 应做 | 坏例惩罚和调用成本有没有用？ | E4 → 奖励只保留 NDCG@10 |
| E6 | 应做 | 冷启动 SFT 是否必要？ | E4 → 起点换成基座 |
| E2 | 可做 | 动态过滤有没有用？ | E1 → 关闭动态过滤 |
| E7 | 可做 | 步级功劳分配（GiGPO）能否超过整条轨迹的 GRPO？ | E4 → 用 verl-agent 的 GiGPO |
| E8 | 可做 | 工具描述或返回格式变化后，Agent 是否稳健？ | 只评测不训练：E4 模型在改写过的工具描述、`search` 只返回 5 个结果等变体环境上评测 |
| E9 | 可做 | 换大一号模型多拿多少？ | E4 → 策略模型换成 Qwen3.5-4B |

- M1 的候选是 E1、E2 中 `dev` 主指标最好的那个，选定后跑一次 `test`。
- M2 的候选是 E4–E7 中 `dev` 主指标最好的那个。
- E8 不参与选择，只为回答稳健性问题；它的变体环境不能用于训练。
- 按宪章的规则，里程碑超时 50% 时从“可做”开始砍，“必做”不砍。

## 8. 算力预算

开工时只有估算；T0 的基准测试和第一轮实验后用实测数据回填。

| 项 | 估算 | 实测 |
|---|---|---|
| E1 L1 GRPO 一轮 | 数小时量级 | |
| B4 生成冷启动轨迹（4000 × 4 条） | 数小时量级 | |
| E3 SFT 一轮 | 1–2 小时量级 | |
| E4 L2 GRPO 一轮 | 十小时量级 | |
| `dev` / `test` 全量评测一次 | 分钟到半小时级 | |

- L2 在 24GB 上显存不够时，按 D3 换到 48–80GB 单卡，并记入 `DECISIONS.md`。
- 单个实验的实测耗时超过估算 2 倍时，先停下来查原因，再决定是否继续。

- 每次运行的配置文件随代码提交；checkpoint 目录名格式为 `<实验ID>-<data_version>-<短 commit hash>`，能反查到配置。
